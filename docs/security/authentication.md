# Локальна автентифікація — TaleSpire GM Logger

## 1. Межі системи (Scope)
Інструмент `tools/drs_release` є локальною CLI-утилітою. Автентифікація виконується виключно в терміналі Game Master'а. Система не взаємодіє з мережею чи грою напряму, що унеможливлює перехоплення вводу через ігровий процес.

## 2. Зберігання облікових даних
* **Паролі:** Не зберігаються у відкритому вигляді. Використовується алгоритм PBKDF2 (HMAC-SHA256, 600 000 ітерацій, 16 байт солі).
* **Верифікатор:** У файлі `drs_release.accounts.json` зберігається лише хеш-верифікатор та унікальна сіль. Майстер-ключ існує лише в оперативній пам'яті під час активної сесії.

## 3. Стійкість до перебору та розкриття імен
* **Блокування:** 5 невдалих спроб поспіль призводять до тимчасового блокування (5, 10, 20, 40, 60 хвилин).
* **Захист від timing-атак:** Перевірка пароля займає однаковий час навіть для неіснуючих користувачів (використовується фіктивна сіль). Повідомлення про помилку завжди загальне: "Автентифікацію відхилено".

## 4. Сесія та Журнал аудиту
* **Сесія:** Має тайм-аут простою (10 хвилин) та абсолютний тайм-аут (60 хвилин). Після команди `exit` стан повністю скидається.
* **Аудит:** Усі події безпеки (init, add-user, login-ok, login-fail, lockout, session-timeout) записуються у файл `drs_release.audit.log`.

## 5. Безпекові вимоги (Трасування)
* **SR-21:** Паролі повинні зберігатися у вигляді стійкого хешу з сіллю (PBKDF2) -> Закриває загрозу підбору пароля з файлу.
* **SR-22:** Система повинна обмежувати кількість невдалих спроб входу (блокування) -> Закриває загрозу Brute-force.
* **SR-23:** Інформація про успішні/невдалі входи та блокування має записуватися в журнал аудиту -> Закриває загрозу відмови від дій (Repudiation).
