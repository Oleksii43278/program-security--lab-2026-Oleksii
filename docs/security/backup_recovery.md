# Резервне копіювання та аварійне відновлення (TaleSpire GM Hub)

## 1. Склад резервної копії
- **Резервується:** стан сервера (`state.json`: клієнти з SHA-256 секретів, реєстр релізів, зашифровані E2EE-звіти сесій), серверний хеш-ланцюг (`ledger.json`), TLS-матеріали (`ca_cert.pem`, `srv_cert.pem`, `srv_key.pem`), безпекові журнали (`gm_security-*.jsonl`, 90 діб), закритий ключ отримувача X25519 та ключі підпису релізів.
- **Не резервується (відтворюється):** вихідний код і документація (Git + GitHub), релізні архіви (відтворювана збірка з тегу), `.venv` і кеші (`pip install -r`), загальні HTTP-логи, активні сеансові токени та лічильники невдач (примусово очищаються у копії).

## 2. Стратегія резервного копіювання
- **Тип:** повна копія щоразу (малий обсяг даних, швидке відновлення з одного файла).
- **Періодичність:** щодня автоматично + позачергово після кожного релізу та перед оновленням.
- **Зберігання (GFS):** 7 щоденних, 4 щотижневих, 6 щомісячних копій.
- **Розміщення (3-2-1):** робоча тека сервера + локальне сховище на іншому диску + щотижнева копія на офлайн-носії.
- **Захист і цілісність:** шифрування `AES-256-GCM` (ключ `scrypt`, N=2^15, парольна фраза >= 12 символів зберігається окремо), зовнішній файл `.sha256`, внутрішній `manifest.json` із SHA-256 кожного файла та перевірка хеш-ланцюга (`gm_hub_backup.py`).
- **Показники відновлення:** **RPO <= 24 год** (для релізів ~0 завдяки позачерговій копії та Git-якорю), **RTO <= 1 год** (фактично < 1 хв).
