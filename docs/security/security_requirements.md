# Безпекові вимоги TaleSpire GM Logger

Ці вимоги доповнюють функціональні вимоги (FR) та походять безпосередньо з моделі загроз.

| ID | Вимога | Критерій перевірки | Закриває загрозу |
| :--- | :--- | :--- | :--- |
| SR-01 | Запис у файл `gm_log.json` (D1) має виконуватися атомарно (запис у тимчасовий файл `tmp_log.json`, а потім перейменування), щоб уникнути часткового запису та пошкодження хеш-ланцюга. | Під час виконання скрипта в операційній системі з'являється тимчасовий файл, який потім замінює основний, а не відбувається пряме дописування у відкритий файл `gm_log.json`. | T-01 |
| SR-02 | Перед виконанням будь-якої операції запису скрипт повинен викликати функцію валідації (P4), щоб переконатися, що існуючий хеш-ланцюг не був пошкоджений до цього моменту. | Якщо файл `gm_log.json` був змінений вручну, спроба додати новий запис через CLI відхиляється з повідомленням про порушену цілісність. | T-01 |

## Прийняті ризики (AR)
| ID | Ризик | Обґрунтування |
| :--- | :--- | :--- |
| AR-01 | Відсутність цифрового підпису записів (Repudiation). | Впровадження асиметричної криптографії та управління закритими ключами надмірно ускладнить інструмент, який призначений для дружніх ігор. Цілісність ланцюга (Tampering) забезпечується SHA-256. |
