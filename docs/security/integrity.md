# Контроль цілісності та автентичності — TaleSpire GM Logger

## 1. Об'єкти контролю

| Об'єкт | Властивість | Механізм | Реакція на невдачу |
| :--- | :--- | :--- | :--- |
| Файл облікових записів | Цілісність + автентичність (локально) | HMAC-SHA256 (окремий ключ, мітка в самому файлі) | Відмова в роботі (fail closed), код 2, запис у журнал |
| Артефакти релізу (збірка) | Цілісність + автентичність походження | SHA-256-маніфест + підпис Ed25519 | Відхилення перевірки з переліком розбіжностей |
| Секрет TOTP | Конфіденційність + цілісність | AES-256-GCM (впроваджено в ЛР6) | Відмова входу (InvalidTag) |

## 2. Обґрунтування вибору
* **HMAC-SHA256 для бази акаунтів:** Файл перевіряє той самий інструмент, що його й пише. Секретний ключ нікому не передається, тому HMAC є ефективним і достатнім захистом від несанкціонованих модифікацій бази (наприклад, зміни ролі користувача).
* **Ed25519 для артефактів релізу:** Збірку отримують кінцеві гравці. Використання асиметричної криптографії дозволяє підтвердити походження збірки (автентичність) за допомогою відкритого ключа, не розкриваючи закритий.
* **Звичайний SHA-256:** Використовується виключно всередині підписаного маніфесту для фіксації вмісту файлів, а не як самостійний засіб захисту.

## 3. Зберігання еталонів та ключів
* **Ключ HMAC:** 32 випадкові байти. Створюється автоматично під час ініціалізації бази та зберігається у файлі `drs_release.accounts.json.key` (додано в `.gitignore`).
* **Ключі Ed25519:** Приватний ключ (`drs_release.signing.key`) зберігається локально у власника (в `.gitignore`). Відкритий ключ (`release_signing.pub`) закомічується в репозиторій як еталон для перевірки гравцями.
