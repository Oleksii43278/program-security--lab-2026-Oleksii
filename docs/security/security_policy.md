# Політика безпеки — TaleSpire GM Logger

## 1. Purpose
Ця політика визначає правила безпечної реалізації механізму криптографічного логування для захисту від підміни історії (Tampering) та відмови (Repudiation).

## 2. Scope
Політика поширюється на вихідний код системи (ядро хешування та модуль зберігання) і не охоплює безпеку операційної системи чи стороннього ПЗ на машині GM.

## 3. Secure Implementation (Безпечна реалізація)
Це ядро політики. Усі операції запису повинні суворо дотримуватися наступних правил:
1. **Сліпе хешування:** Будь-який текст події, переданий користувачем, хешується "як є", без жодних модифікацій (trim, lower, форматування), щоб гарантувати ідентичність при валідації.
2. **Атомарний запис:** Запис нового логу в файл (append) повинен виконуватися атомарно (запис у tmp-файл -> перейменування), щоб уникнути пошкодження файлу при раптовому вимкненні живлення або краші системи.
3. **Обмеження полів:** Система записує строго 4 поля: `timestamp`, `event_text`, `previous_hash`, `hash`. Додавання нових полів вимагає окремого коміту `[SEC]` з оновленням документації.
4. **Неперервність ланцюга:** Хеш поточного запису завжди обчислюється на основі `hash` безпосередньо попереднього запису в файлі. Жодних винятків.

## 4. Exceptions (Свідомі винятки)
Наступні заходи безпеки свідомо не впроваджуються через специфіку інструменту:
* **Мережевий бекап логів:** Система не відправляє логи на зовнішній сервер, оскільки працює повністю офлайн.
* **Шифрування файлу (Confidentiality):** Лог-файл зберігається у відкритому вигляді (JSON), оскільки мета — цілісність, а не конфіденційність, і гравці повинні мати змогу легко його прочитати.
* **Автоматизований динамічний аналіз (DAST):** Не застосовується, оскільки інструмент не має мережевих інтерфейсів для сканування.
