# Вимоги до системи за ISO/IEC/IEEE 29148

## Функціональні вимоги (FR)

| ID | Вимога | Критерій перевірки |
| :--- | :--- | :--- |
| FR-01 | Система повинна генерувати хеш SHA-256 для кожного нового запису журналу. | У вихідному JSON-файлі журналу кожний об'єкт має поле `hash` довжиною 64 символи. |
| FR-02 | Хеш поточного запису має обчислюватися з використанням хешу попереднього запису. | Ручна зміна тексту першого запису у файлі призводить до того, що функція валідації позначає всі наступні записи як недійсні. |
| FR-03 | Система повинна мати функцію перевірки цілісності всього журналу при запуску. | При завантаженні існуючого файлу система виводить статус `VALID` або номер рядка з розбіжністю. |

## Нефункціональні вимоги (NFR)

| ID | Вимога | Критерій перевірки |
| :--- | :--- | :--- |
| NFR-01 | Система не повинна створювати мережевих з'єднань. | Моніторинг процесу через Wireshark не фіксує жодного вихідного пакета від застосунку. |
| NFR-02 | Формат зберігання журналу має бути людиночитним. | Файл журналу є валідним JSON-документом, який відкривається у стандартному текстовому редакторі. |
