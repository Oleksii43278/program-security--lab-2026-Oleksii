# Діаграма потоків даних (DFD)

Діаграма описує рух інформації в системі. Елементи пронумеровані наскрізно для побудови моделі загроз.

## Зовнішні суб'єкти (E)
* **E1** — Game Master (GM): користувач, що фізично взаємодіє з клавіатурою.
* **E2** — Операційна система: файлова система для зберігання.

## Процеси (P)
* **P1** — `InputProcessor`: приймає текстовий ввід від GM.
* **P2** — `HashEngine`: запитує останній хеш з файлу та обчислює поточний SHA-256.
* **P3** — `StorageManager`: виконує серіалізацію в JSON та запис на диск.

## Сховища даних (D)
* **D1** — `gm_log.json`: локальний файл на диску, де зберігається хронологія подій.

## Потоки даних (F)
* **F1 (E1 -> P1):** Текстовий опис події.
* **F2 (P1 -> P2):** Структурований об'єкт події.
* **F3 (P2 -> D1):** Запит на читання попереднього запису.
* **F4 (D1 -> P2):** Значення попереднього хешу.
* **F5 (P2 -> P3):** Криптографічно підписаний об'єкт події.
* **F6 (P3 -> D1):** Операція запису нового об'єкта.

## Межі довіри (TB)
* **TB1 (Межа процесу):** Відокремлює внутрішню оперативну пам'ять скрипта (P1, P2, P3) від зовнішньої файлової системи (D1). Після перетину межі в D1 дані вважаються недовіреними.
